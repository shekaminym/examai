# EXAM AI 3.4.1

- Windows при повторному вході використовує той самий ідентифікатор пристрою з локального профілю. Після підтвердження Google можна завершити найстаріший сеанс без активного запиту. Одночасно працює лише один Cloud-сеанс акаунта.
- У розділі «Підписки → Обліковий запис» є «Змінити акаунт» і «Вийти». Для кожного Google-акаунта EXAM AI використовує окремі Notes, історію та локальні налаштування Gemini API key. Попередня спільна база лишається доступною в локальному режимі.
- Адмінка використовує окремий серверний сеанс із захищеним cookie. Після оновлення сторінки зберігається поточний розділ. Кожний захищений запит перевіряє роль, а зміни через браузер також перевіряють джерело запиту.
- Таблиця користувачів і Windows-клієнт показують актуальний стан доступу. Тривалість нараховується за серверним часом лише в межах чинного сеансу Cloud.
- Owner може переглянути стан Google-підтвердження та пристрої, завершити сеанси, деактивувати або видалити вибрані записи. Перед видаленням сервер перевіряє резервну копію SQLite. Акаунти Owner захищені від видалення.
- Очищення журналу приховує записи в таблиці за обраний період. Серверний аудит зберігає самі події і факт очищення.

## Дії користувача

Якщо Windows показує ліміт пристроїв, завершіть сеанс на іншому пристрої або натисніть «Завершити старий сеанс» після підтвердження Google. У веб-адмінці Owner може відкрити «Користувачі → Дії → Пристрої та стан акаунта».

## Оновлення сервера

Нові таблиці SQLite створюються при запуску. Старі таблиці ліцензій, сесій, звітів і запрошень залишаються в базі. Перед оновленням зробіть SQLite backup і перевірте запуск на копії. Для відкату поверніть попередні файли серверного коду та перезапустіть застосунок. Відновлення SQLite з резервної копії потрібне лише якщо треба повернути дані до конкретного стану: воно також відкине нові записи після моменту копіювання.
