# Облікові записи та адміністрування

## Порядок оновлення

1. Оновіть сервер перед Windows-клієнтом. Під час запуску сервер автоматично створює таблицю `display_name`; наявні профілі та ліцензії залишаються без змін.
2. Після оновлення сервера перевірте вхід через Google на тестовому профілі. Нове поле імені над кнопкою входу зберігається в серверній SQLite за Google `sub` і повертається з `/account`.
3. У новому клієнті без збереженого сеансу при запуску відкриваються загальні налаштування з входом Google. Користувач із чинним сеансом входить автоматично.

## Доступ до Gemini

Кожен вхід створює окремий токен EXAM AI для пристрою. Сервер перевіряє ліцензію та ліміти конкретного користувача й викликає Gemini зі своїм секретним ключем. Користувачеві не потрібно створювати чи отримувати Google API Key. Ключ сервера не передається клієнту. Квоти Google діють на рівні Cloud-проєкту, тому створення багатьох ключів у одному проєкті не дає окремих квот. Для Cloud-відповідей потрібна налаштована серверна змінна `EXAMAI_CLOUD_GEMINI_KEY`.

## Дії власника

- У розділі «Користувачі» можна безповоротно видалити записи з адресами `@example.test`, їхні сеанси, запрошення, звіти та пов'язаний журнал. Власників видалити цією дією не можна. Інші адреси залишаються. Резервні копії ця дія не змінює.
- У розділі «Дії» власник може надати справді безстроковий доступ. Доступ із кінцевою датою позначається «До дати», безстроковий — «Назавжди».
- У «Журналі дій» власник може очистити останні записи за обраний проміжок. Записи про очищення зберігаються, щоб дія залишалася видимою.

Ці дії не запускаються автоматично під час оновлення. Необхідно увійти як власник і підтвердити кожну з них у панелі.
